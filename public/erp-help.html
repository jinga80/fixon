시작하기

FixOn ERP는 치과의 디지털 스플린트 디자인 → 기공소 디자인 작업 → 그래피 3D 인쇄/조립 → 환자 적용까지 전체 워크플로우를 관리하는 운영 시스템입니다.

💡 5분 안에 시작하기
1. ERP 접속 → 우상단 역할 전환 → 본인 역할 선택
2. 사이드바에서 메뉴 탐색
3. 본 가이드의 역할별 가이드 참고

전체 워크플로우

주문 12단계

접수 → 디자인 대기 → 디자인 중 → 디자인 완료 → 생산 대기 → 인쇄 → 조립 → QC → 배송 → 수령 → 환자 적용 → 정산 완료

시스템 구조

FixOn ERP는 단일 HTML 파일로 동작하며 4개 stakeholder가 각자의 역할로 관리합니다.

역할주요 화면핵심 기능
🦷 치과대시보드 / 신규 주문 / 환자 관리 / 결제주문 등록, 환자 데이터 관리, 적용 완료, 결제
🔧 기공소작업 큐 / 완료 목록 / 통계스캔 검토, FixOn 디자인 SW 작업, 디자인 완료
🖨️ 그래피생산 큐 / 조립 / QC / 배송 / 재고3D 프린팅, 조립, 품질 검수, 배송 등록
⚙️ FixOn전체 대시보드 / 정산 / 거래처 / 품질운영 총괄, 매출 분배, 거래처 관리

치과 가이드

1️⃣ 환자 등록

"환자 관리" 메뉴에서 신규 환자를 등록합니다. 이름, 나이, 성별, 진료 비고를 입력합니다.

2️⃣ 신규 주문

"신규 주문" 메뉴에서:

  1. 환자 선택
  2. 스캔 방식 선택 (구강스캐너 / 인상체 데스크탑 스캔)
  3. 스캐너 모델 + 부위 선택
  4. 스캔 파일 업로드 (또는 샘플 사용)
  5. 노즐 레이아웃 프리셋 선택 또는 3D 디자이너에서 직접 배치
  6. 주문 등록 → 자동으로 기공소로 의뢰 발송

3️⃣ 주문 추적

"주문 목록"에서 진행 상태를 실시간 확인합니다. 알림 🔔으로 주요 단계마다 안내받습니다.

4️⃣ 수령 및 적용

배송이 도착하면 "수령 확인" → 환자 적용 후 "환자 적용 완료" 클릭 → 자동 정산.

기공소 가이드

📥 작업 큐 확인

치과로부터 들어온 디자인 의뢰가 칸반 형태로 표시됩니다. 카드를 클릭해 스캔 데이터를 검토합니다.

🔍 스캔 검토

스캔 품질이 적합한지 확인:

  • 품질 OK → "디자인 시작" 클릭 → designing 상태
  • 품질 부족 → "재스캔 요청" 클릭 → 사유 입력 → 치과로 반려

✏️ 디자인 작업

FixOn 디자인 SW (또는 3D 디자이너)로 스플린트 설계 → "디자인 완료" → 자동으로 그래피 생산 큐로 인계.

그래피 가이드

🖨️ 인쇄

"생산 큐"에서 카드 클릭 → "인쇄 시작" → 가용 프린터 자동 배정 → 소재(TC-85) 사용량 자동 차감.

🔧 조립

인쇄 완료 후 "조립" 페이지로 이동:

  • 분사 노즐 4개 삽입
  • 어댑터 결합
  • 튜브팁 연결
  • 수밀 테스트

✔️ QC

6-axis 검사: 치수 정확도, 노즐 분사, 표면 마감, 어댑터 결합, 수밀, 환자 적합성

  • 통과 → 송장 자동 생성 → 배송
  • 실패 → 재생산 큐로 회귀

FixOn 관리자 가이드

📊 전체 대시보드

모든 주문, 매출, stakeholder별 처리 현황을 한 화면에 모니터링.

🏢 거래처 관리

치과/기공소/그래피의 신규 등록 및 계약 관리.

💰 정산

환자 적용 완료된 주문에 대해 매출을 자동 분배: 기공소 / 그래피 / FixOn 수수료.

💲 단가 정책

주문 1건당 분배율 설정. 합계 검증 자동.

3D 디자이너 사용법

주문 모달에서 "🎨 3D 디자이너" 버튼으로 진입. 5단계 wizard 흐름:

Step 1: Import

구강스캐너 / 인상체 / 샘플 중 선택 → STL 업로드 또는 드래그앤드롭

Step 2: 치아 인식

"치아 자동 인식" 클릭 → 14개 FDI 라벨 자동 부여

Step 3: Splint Fit

"Template Fit" 클릭 → splint0306 템플릿이 환자 스캔에 affine fit. Scale 슬라이더로 미세 조정.

Step 4: 노즐 배치

  • Hover preview: 마우스 올리면 ghost nozzle이 표면 따라다님
  • FDI 차트 클릭: 우측 14-cell 차트에서 자동 배치
  • Mirror 모드: 한쪽 클릭 → 반대쪽 자동 배치
  • Drag: 노즐 드래그로 표면 따라 이동
  • Ctrl+Z / Ctrl+Y Undo/Redo

Step 5: Export

STL 다운로드 (생산용) / JSON (설계 데이터) / 주문에 적용

용어 사전

FDI 치아 번호 체계

국제 표준 두 자리 번호: 첫 자리=사분면 (1=상악우측, 2=상악좌측, 3=하악좌측, 4=하악우측), 둘째 자리=중앙에서의 거리 (1=중절치, 2=측절치, 3=견치, 4=제1소구치, 5=제2소구치, 6=제1대구치, 7=제2대구치).

주요 용어

  • 스플린트 (Splint): 교합안정장치, 환자 치아에 끼우는 맞춤 장치
  • 노즐 (Nozzle): 스플린트의 분사 부위, 잇몸 마사지/치주 케어용
  • 구강스캐너 (Intraoral Scanner): 치과에서 직접 환자 구강 스캔
  • 인상체 / 모형 스캔: 인상재로 본 뜬 후 데스크탑 스캐너로 스캔
  • QC (Quality Control): 품질 검수
  • TC-85: 그래피 3D 프린팅용 의료용 레진

자주 묻는 질문 (FAQ)

Q1. 스캔 파일 형식은 무엇을 지원하나요?

A. STL (binary/ASCII), PLY, OBJ를 지원합니다. STL이 권장됩니다.

Q2. 노즐 위치를 잘못 지정한 경우 어떻게 수정하나요?

A. 주문 모달에서 "노즐 위치 수정" 또는 "3D 디자이너로 직접 배치"를 사용해 변경할 수 있습니다.

Q3. QC 실패 시 어떻게 처리되나요?

A. 자동으로 print_queued 상태로 회귀하고, 재작업 큐에 등록됩니다. 사유는 타임라인에 기록됩니다.

Q4. 주문 상태를 되돌릴 수 있나요?

A. QC 실패 외에는 일반적으로 되돌리지 않습니다. 잘못된 진행은 FixOn 관리자에게 문의하세요.

Q5. 결제는 어떻게 처리되나요?

A. 환자 적용 완료 시점에 정산 대기로 전환되며 FixOn 관리자가 정산을 진행합니다.

Q6. 모바일에서도 사용 가능한가요?

A. 네, 모바일 ERP를 별도로 제공합니다.

Q7. 분석 리포트는 어디서 보나요?

A. 분석 대시보드 또는 리포트 페이지에서 확인.

Q8. 데이터는 어디에 저장되나요?

A. 브라우저의 localStorage에 저장됩니다 (현재 데모 단계). 향후 백엔드 연동 예정.

Q9. 다른 환자의 정보를 볼 수 있나요?

A. 본인 거래처(치과/기공소)의 환자만 보입니다. FixOn 관리자는 전체를 볼 수 있습니다.

Q10. 3D 디자이너에서 splint 모양이 환자마다 다른가요?

A. 네, 각 환자의 스캔에 맞춰 splint0306 template를 affine fit하여 환자별로 다른 형태가 생성됩니다.

Q11. 재스캔이 필요한 경우는?

A. 기공소가 스캔 품질 부족 판단 시 "재스캔 요청"을 보냅니다. 치과 대시보드에 알림이 표시됩니다.

Q12. 단가 정책은 누가 변경하나요?

A. FixOn 관리자만 변경 가능합니다. (단가 정책 메뉴)

Q13. STL 파일이 file://에서 로드 안 됩니다.

A. 샘플 STL은 인라인되어 있어 file://에서도 동작합니다. 사용자 STL 업로드는 FileReader로 처리됩니다.

Q14. 어댑터/튜브팁 위치는 어디서 지정하나요?

A. 그래피 조립 단계에서 처리됩니다. 디자이너에서는 노즐만 배치합니다.

Q15. QC 인증서 출력은?

A. QC 센터의 인증서 탭에서 통과한 주문에 대해 다운로드 가능.

Q16. Mirror 모드는 어떻게 동작하나요?

A. ON 상태에서 #46 클릭 → #36에도 자동 배치 (좌우 대칭). 비대칭 환자는 OFF.

Q17. 알림은 어디서 보나요?

A. ERP 우상단 🔔 아이콘 또는 모바일 메시지 탭.

Q18. 데이터를 초기화하려면?

A. 사이드바의 "🔄 데이터 초기화" 버튼 또는 모바일 설정 → 초기화.

Q19. 새로 추가된 페이지는 무엇인가요?

A. 분석 대시보드, 메시지 hub, 리포트 생성기, QC 센터, 모바일 컴패니언, 도움말 (이 페이지)이 추가되었습니다.

Q20. 보안 / 개인정보는 어떻게 관리되나요?

A. 현재 데모 단계로 localStorage만 사용. 운영 단계에서는 의료정보보호법 준수 백엔드와 암호화 적용 예정.
