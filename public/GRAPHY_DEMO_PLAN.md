# FixOn × Graphy 사업 미팅 시연 준비 문서

> **목적**: 그래피 의사결정자 앞에서 **"이 소프트웨어 하나로 FixOn 사업 운영이 즉시 가능하다"** 를 5~10분 안에 증명
> **메시지**: 쉽고 (easy) · 빠르고 (fast) · 정교하게 (precise) · 지금 당장 (today)

## 0. 시연 직전 반드시 처리할 4가지 (Demo-Blocking)

이 4가지가 데모 도중 깨지면 신뢰가 무너집니다. 다른 모든 것보다 우선.

### ① 주문 상태 흐름의 일관성 — `rescan_requested` 정식 편입
- **현상**: 재스캔 요청 상태로 들어간 주문은 타임라인 진행률 표시가 깨지고(인덱스 -1), 모바일에서 다음 단계 진행이 잘못 작동함
- **조치**: `STATUS_FLOW` 배열과 모바일/분석 페이지의 인덱싱 로직에 `rescan_requested`를 정식 편입하거나, 별도 분기로 처리
- **데모 영향**: "주문 진행 추적" 시나리오에서 갑자기 0%로 돌아가면 사업 미팅에서 즉사

### ② 페이지 간 상태 라벨 통일
- **현상**: 데스크탑은 "조립 중", 모바일은 "조립" — 같은 주문이 페이지 이동 시 다른 라벨로 보임
- **조치**: `STATUS_LABEL` 단일 source of truth로 통일 (또는 mobile만 desktop 따라가게 수정)
- **데모 영향**: 시연자가 데스크탑/모바일 전환할 때 "이거 같은 주문 맞아?"라는 질문 차단

### ③ 디자이너 → 그래피 자동 인계
- **현상**: 3D 디자이너에서 노즐 배치 후 "주문에 적용" 시 customNozzles만 저장되고, 실제 인쇄용 STL은 사용자가 수동 다운로드해야 함
- **조치**: "주문에 적용" 시 통합 STL을 자동 생성해 주문에 첨부 (Blob/data URL을 order.designSTL에 저장). 그래피 화면에서 다운로드 가능
- **데모 영향**: "치과가 디자인 → 그래피가 출력" 핵심 가치 demo의 마지막 연결고리

### ④ 시연용 데이터 시드 정비
- **조치**: `localStorage.removeItem('fixon-erp-state-v5')` 후 새로 시드되는 12개 주문이 12개 상태에 골고루 분포하도록 재배치 (현재는 일부 상태가 비어있을 수 있음)
- **추가**: 실명 대신 demo persona (예: "박○○", "이○○") 사용 일관성 확인
- **데모 영향**: 모든 메뉴를 클릭해도 빈 화면이 안 나와야 함

## 1. 시연 시나리오 (10분 황금 흐름)

총 5장면으로 구성. 각 장면은 1~2분.

### 장면 1 (1분) · "한눈에 보는 운영 현황" — 신뢰 점화
- **시작 화면**: erp.html → FixOn 관리자 역할 → 전체 대시보드
- **보여줄 것**:
  - 12개 주문이 12개 상태에 분포된 파이프라인
  - 활성 거래처 카운트 / 이번 달 매출
- **멘트**: "FixOn은 이미 운영 중인 워크플로우를 그래피와 함께 확장합니다. 지금 보시는 것은 시뮬레이션이지만, 백엔드만 붙으면 그대로 실 운영입니다."

### 장면 2 (2분) · "치과 신규 주문 30초 컷"
- **역할 전환** → 치과 (드롭다운에서 클릭)
- **신규 주문 → 환자 선택 → 샘플 STL 사용 → 표준 4-노즐 → 주문 등록**
- **멘트**: "치과는 30초 안에 의뢰가 끝납니다. 환자 식별·스캔 첨부·노즐 위치 요청까지 한 화면."

### 장면 3 (3분) · "3D 디자이너 — 핵심 차별점"
- **주문 모달 → 🎨 3D 디자이너로 직접 배치**
- **시연 흐름**:
  1. STEP 1: 샘플 스캔 자동 로드 (이미 진행됨)
  2. STEP 2: "치아 자동 인식" 클릭 → 14개 FDI 라벨 등장
  3. STEP 3: "Template 자동 Fit" 클릭 → splint이 환자 스캔에 자동 정렬
  4. STEP 4: FDI 차트에서 #46 클릭 → Mirror 토글 ON → #36 자동 동시 배치
  5. STEP 5: "STL 다운로드" 또는 "주문에 적용"
- **멘트**: "스캔 → 디자인 → 출력용 STL이 한 화면에서 끝납니다. 다른 CAD가 필요 없어요."

### 장면 4 (2분) · "그래피 생산 큐 흐름"
- **역할 전환** → 그래피
- **생산 큐 → 인쇄 시작 (프린터 자동 배정 + 소재 차감) → 조립 체크리스트 → QC 통과 → 송장 자동 생성**
- **멘트**: "그래피팀이 받은 주문은 한 번의 클릭으로 다음 단계로 진행됩니다. 별도 시스템·엑셀 없이."

### 장면 5 (2분) · "분석·정산·확장"
- **사이드바 → 분석 대시보드**: 6개 KPI + 6개 SVG 차트
- **사이드바 → 리포트 생성기 → 정산 명세서 → 인쇄/HTML 다운로드**
- **사이드바 → 환자 포털** (새 탭): 환자 입장에서 "ORD-2026-XXXX" 입력 → 진행 상황 실시간 확인 (PII 마스킹)
- **멘트**: "분석·리포트·환자 안내까지 같은 시스템 안에서. 그래피가 제조에 집중하시면, 운영은 FixOn이 완성합니다."

## 2. 시연 전 30분 체크리스트

| 항목 | 확인 방법 | 통과 기준 |
|---|---|---|
| 데이터 초기화 | localStorage 삭제 후 새로 진입 | 12개 주문이 모든 상태에 분포 |
| 5개 시나리오 리허설 | 위 장면 1~5 직접 클릭 | 멈춤·빈 화면·에러 없음 |
| 3D 디자이너 STL 로드 | 디자이너 진입 후 splint 형상 표시 | 흰색 투명 splint가 명확히 보임 |
| 노즐 capsule 위치 | 표준 4-노즐 미리보기 | 4개 capsule이 splint에 자연스럽게 부착 |
| 모바일 뷰 | erp-mobile.html 열기 + 같은 주문 ID 검색 | 데스크탑과 동일 정보 표시 |
| 인쇄 프리뷰 | 리포트 인쇄 버튼 (Cmd+P) | 흰 배경 + 검정 텍스트 + 깔끔한 레이아웃 |
| 분석 차트 | 6개 차트 모두 데이터 표시 | 빈 차트 없음 |

## 3. 시연 직후 사업 협상에 활용할 차별점 5가지

이 다섯 가지를 한 슬라이드/한 페이지에 정리해 미팅 자료로 제출.

1. **Single-pane workflow** · 치과·기공소·그래피·관리자 4개 stakeholder가 한 시스템에서 동작. 별도 SW·엑셀·이메일 운영 불필요
2. **3D 디자인 내장** · 환자 스캔에서 출력용 STL까지 5-step wizard. 외부 CAD 의존성 0
3. **즉시 운영 가능** · 11개 sub-page (분석·메시지·리포트·QC·재고·캘린더·검색·자동화·환자포털·도움말·모바일) 이미 작동
4. **그래피 친화** · 생산팀 대시보드, 프린터 가동 현황, TC-85 재고 자동 차감 + 자동 발주 규칙
5. **확장성** · localStorage 기반 데모 → 동일 데이터 모델 그대로 백엔드 이관 가능. 기존 그래피 시스템과 API 통합 여지 명확

## 4. 시연 직후 30일 안에 추가 작업할 4가지

미팅에서 "이거 좋은데 우리 환경에 맞춰서 시작 가능?"이라는 질문이 나오면 답할 수 있어야 함.

### A. PII 안전 처리 (개인정보보호법 대응)
- FixOn 관리자 화면에서 환자 실명을 마스킹 (`김OO → 김**`)
- 신규 주문 폼에 동의 체크박스 3종 (수집·제3자 제공·민감정보)
- → 그래피 측 법무·컴플라이언스 부서에 "이미 고려됨"을 보여줄 수 있음

### B. 의료기기 추적성 (UDI/Lot)
- 주문 모델에 `udi`, `lotNo`, `mfgDate`, `expiryDate` 필드 추가
- QC 통과 시 자동 생성 + 인증서에 표기
- → 식약처 의료기기 추적관리 의무 충족 (스플린트는 Class 2)

### C. 그래피 시스템 연동 인터페이스
- 주문 → STL/JSON export를 webhook 또는 폴링으로 그래피 생산 시스템에 자동 전달하는 stub 설계 문서
- 현재 수동 다운로드 → 자동 push 가능 구조 명시

### D. 백엔드 이관 청사진
- 현 localStorage 스키마 (`orders`, `patients`, `clinics`, `customNozzles`, `timeline`)를 RDB 테이블로 1:1 매핑 가능
- API 명세 초안 (REST + WebSocket 알림)

## 5. 미팅 후 묻혀도 되는 항목 (지금은 무시)

다음은 이번 미팅에서 우선순위 아님. 본 계약 이후 백로그.

- ARIA / 키보드 접근성 전면 개편 (지금은 마우스 시연이라 영향 없음)
- 다국어 (i18n) — 한국어 단일로 충분
- 라이트 모드 — 다크 모드가 더 prosumer 인상
- AI 노즐 위치 추천 — "있으면 좋다" 수준, 본 계약 후 R&D
- 결제 게이트웨이 통합 — 정산 표시만으로 충분
- DICOM/CT 임포트 — 스플린트 디자인엔 STL로 충분
- 멀티 테넌트 — 단일 운영자 가정으로 충분
- 단축키 / 코드 quality refactor — 사용자가 보지 않는 영역
